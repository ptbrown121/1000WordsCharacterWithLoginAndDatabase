## Part 2 — Rules deltas: changes required

Ordered by recommended implementation sequence. Each item lists the rule source page,
the affected files, and a size estimate.

### Phase 1 — Tag catalog and data corrections (small, high confidence)

1. **Add the `Sticky` tag (BD 4).** New in the v5.02 glossary (p.78): "effect lasts
   1 minute after call." Used by Ammo Builder lines and reagents.
   Files: `js/pool.js` (`TAG_XP_CATALOG`). Tests: tag XP estimate.

2. **World tag now costs 3 XP.** p.63: "A tile with the 3 XP World Build tag chains
   your Homeworld tile." The app currently scores World at 0 XP
   (`classifyTagForXp` → `{ xp: 0 }`). Keep the existing no-duplicate-surcharge and
   tag-limit exemption behavior; change only the XP.
   Files: `js/pool.js`. Tests: update `pool.test.js` world-tag cases.

3. **Bestial/Celestial tags are 2 XP on skill tiles, 4 XP elsewhere.** Glossary lists
   `X 2/4`; pp.61–63: "For 4 XP, add a Bestial tag to a Trait, Story, or Gear tile"
   (Celestial: Trait or Story). The catalog currently prices both flat 2. This needs
   tile-type context in `estimateTileXpDetails` (it already receives `options`; pass
   tile type through).
   Files: `js/pool.js`, call sites in `js/ui/modals.js`, `js/rules-review.js`.

4. **Crowd ranges are missing.** Space & Time table column Crowd (+3): Crowd 1 = 1 XP,
   Crowd 2 (Sweep) = 2, Crowd 5 = 3, Crowd 10 = 4, Crowd 50 = 5, Crowd 100 = 6,
   Crowd 500 = 7, Crowd 1000 = 8. Several Augur spells use `Crowd N` ranges.
   Add `crowd N` parsing (like `hitch N`) so it is priced and exempt from tag limits
   as a Range tag.
   Files: `js/pool.js` (`RANGE_DURATION_XP`, `getMechanicalBaseTag`), spell builder
   range options.

5. **Add the `Kick` weapon template.** Melee/Touch table (p.30): Kick — Athletics —
   starting tag Throw.
   Files: `js/pool.js` (`WEAPON_TEMPLATES`).

6. **Titan tag family (catalog entries even if the subsystem waits).** p.69: `Titan`
   is +3 XP on any tile. Titan ability tags (Action Hero, Boost, Coup de Grace,
   Ground Zero, Interception, Kill Shot, Pull Punch, Shake Off, Sterner Stuff,
   Turn Them, Under Cover, Zero In) ride the Titan pool. Add `titan` (3 XP, exotic,
   limit-exempt) so sheets using it price correctly; ability tags can default like
   other exotic spends.
   Files: `js/pool.js` (`TAG_XP_CATALOG`, `EXOTIC_TAGS`).

### Phase 2 — Shield building (significant; flagged by the GM update)

Source: System Concept—Tags (p.13), Armor Types (p.29), Shield Tags (p.39),
Taking Injury (p.42), examples: `boxing cesti` (Crit: DOWN + Shield: DOWN as separate
tags), `jousting plate mail` (Shield: BREAK KO BLEED), `stylish leather jacket`
(Shield: JOLT).

Rules to implement:
- **Shield tags are a first-class tag type on Gear** (both armor and weapons). Cost is
  the same per-tag table as Crits — already true in `CRIT_SHIELD_XP` — and Hard armor
  discounts them by 1 — already true via `hardArmorDiscountable`. What's missing is
  *behavior and UI*, not pricing.
- **Each Shield tag blocks one matching inbound Crit** after Grit fails
  ("each Shield tag blocks a matching inbound Crit. Shield tags trigger only when
  needed").
- **The same tag can appear as both Crit and Shield on one weapon** ("They are
  separate") — duplicate-pricing must key on the prefixed form (`Crit: DOWN` vs
  `Shield: DOWN` are *not* duplicates of each other). Today `getDuplicateKey` strips
  the `crit:`/`shield:` prefix, so `Crit: DOWN` + `Shield: DOWN` is wrongly charged a
  +2 duplicate surcharge. Fix the key to include the category.
- **Armor Soak applies only if the armor tile is called** (p.42). The vitals Soak
  display can keep summing all worn armor, but the defense resolution panel should let
  the player pick which armor tile was called and apply only its Soak/Shields.
- **Weapon Shield tags (parry) require the weapon ready as a defense** — GM
  adjudicated; the defense panel should list weapon shields with that caveat rather
  than auto-applying.
- **Shield items as armor entries.** The armor table now names shield items
  (buckler shield = Open Hard; tower shield = Full Hard with Base Soak +1). Consider an
  `ARMOR_TEMPLATES` list mirroring `WEAPON_TEMPLATES` so players can pick named
  examples per material/coverage cell; minimum: document in the armor modal helper
  text that shields are built as armor.

Work items:
1. `js/pool.js`: fix `getDuplicateKey` for Crit/Shield prefixes; add
   `getTileShieldTags(tile)` helper.
2. `js/ui/modals.js`: add a Shield tag picker on Gear (same list as Crit picker,
   writes `Shield: X`).
3. `js/ui/resolution.js` (defense mode): incoming-crits field becomes structured —
   match against active Shield tags from the called armor (auto) and ready weapons
   (opt-in checkbox), show which crits are blocked vs land.
4. `js/ui/armorSoak.js` / vitals: indicate "applies when called" on armor soak
   sources.
5. Tests: duplicate-key fix, shield matching in defense summary.

### Phase 3 — Resolution and combat workflow gaps (medium)

These were already "recommended" in the v5.01 audit; v5.02 keeps them all and adds
detail, so they stay on the list:

1. **Freebie die helper** (p.25): once per test, before or after roll, must duplicate
   a die already in pool, costs EN equal to the die's ▟. Add beside Extra Dice with
   EN deduction and once-per-test guard. (Id Shadow spend and Titan spends can hook
   here later.)
2. **Chain limits** (p.25): a chain cannot call more tiles than the ▟ of the Chained
   tile; each maxed die used costs 1 resource. `compilePool` currently has no chain
   length check. Enforce the length limit (or warn), and surface the maxed-die cost
   at resolution time.
3. **Range/Duration on the fly** (pp.52–53): after assigning attack/impact dice, a
   spare die ≥3 raises a Range or Duration tag one increment; second die needs ≥4,
   third ≥5. Instant, Sustain, and Rite durations cannot be modified. Add a
   resolution assignment option like the existing ammo flow.
4. **Press tracker** (p.37): per-fight counter; 1 RX = Move, 2 RX = Action; repeating
   the previous action −1; each Press or Haywire raises future Press costs by 1;
   reset at fight end. Tag hooks: Fast (−1 on that weapon's attacks), Recoil (+1),
   Reticle (Cyber: spend 1 Core to skip the counter increase). A small combat panel
   widget with an RX spend button is enough.
5. **Status dashboard** (pp.42–43): derive statuses from pools — 0 EN Fatigued,
   0 RX Cornered, 0 HP Riven, EN+RX Exhausted, EN+HP Unconscious, RX+HP Paralyzed,
   all three = near Death. Add Fast/Sticky crit checkboxes mirroring the character
   sheet's Crits Dashboard (p.80) so PAIN/JOLT/SLOW/DOWN/BLEED/WOUND and special
   crits can be tracked and feed the healing panel.
6. **Glitch flaw and haywire** (p.65): Glitch counts 1s *and* 2s for haywire.
   `calculateOptimalTotal` hardcodes 1s. Thread a `haywireOn` threshold from called
   tiles' flaws.

### Phase 4 — Subsystem buildouts (large, one per PR)

1. **Cyber Core pool** (p.64). Each Cyber-tagged tile contributes 1 Core. Core's
   *current value adds to Grit*. Spend actions per tag (Antivenin, Boost, Breathless,
   Charged, Enhanced, Fireproof, Machine, Plated, Reticle, Sleepless, Spacewalk,
   Wired); Tether/Unborn/Zenith at 4 XP (already cataloged). Recovery: 1/hour, or
   full with battery pack / supercharger hour. Model like Shadow: a derived max from
   tiles + current value + spend buttons listing available Core abilities from the
   character's actual tags. This was the audit's #4 recommendation; v5.02 confirms
   the design.
2. **Titan subsystem** (p.69) — *new in v5.02*. Titan pool = count of Titan tags
   (3 XP each, any tile). When a Titan tile is used, reroll any pool die rolling
   below its ▟. Spend 1 Titan: gain an Add, or maximize a die (Grit/Impact die when
   no Titan tile used). Titan can be spent as Core or Shadow if those pools exist.
   Heroism/Villainy (H/V) score tracker for recovery; GM resets scores for Titan
   points at story beats. Costume: a Titan Identity Gear/Story tile with a **third
   color box** and all Build/Shield/Detail tags at −1 XP.
3. **Third color box support** (Titan Costume p.69, Celestial Homeworld p.63). The
   data model caps `tile.boxes` at 2 (`data.js` and `pool.js` both `.slice(0, 2)`).
   Allow 3 boxes when the tile is flagged Homeworld or Titan Identity; resource maxes
   and call-color matching follow automatically once the cap is conditional.
4. **Stranger completion** (pp.61–63):
   - Bestial: each Bestial-tagged tile grants **+1 to any one resource pool** (player
     choice — store the chosen resource on the tag/tile, feed
     `calculateResourceMaxes`); Pace = Walk note on the sheet.
   - While X: a "current form" selector that buries/unburies `While X` tiles in one
     toggle (the data model already supports buried).
   - Celestial: Aural/Astral rank = count of Celestial tiles; show projected-sense
     range (Linear column) or out-of-body time (Time column) from the rank.
   - Add the Celestial-side and space-setting skill lists (Dreaming, Kinesis,
     Network +2 XP exotic; Adapt, Dogfight, Gunner, Hardsuit, Navigate, Psinger,
     Vibro, Xenology, Zappers at normal cost) to skill pickers / AI creation data.
5. **Repartee / Hinders** (p.41). New Gear concept: a Hinder is a verbal-attack Gear
   tile with a **−3 XP rebate**, a Range (Earshot/Visual), and a Crit. Attack-type →
   skill → injured pool mapping (Guile→RX/HOLD, Menace→RX/FEAR, Presence→EN/GOAD,
   Reason→Hidden/REVEAL, Wiles→EN/VOW). Defense uses the same skill list but cannot
   mirror the attacker's skill. Implementation: new `gearSubtype: 'Hinder'` with the
   rebate in `estimateTileXpDetails`, plus a defense-panel note. Violet's
   `cutting one-liner` (p.67) is the worked example.
6. **Gizmo/Sliver limits** (p.68): gizmos ≤ MIND+FOCUS ▟; slivers ≤ BODY+POWER ▟;
   a Gizmo has ▟ HP, may Break on Haywire, cannot use Qi/Id; Gizmo without a skill
   chain costs only 2 XP. Add review-strip checks (counts vs stat caps) and the
   2-XP unchained variant; deeper automation can wait.
7. **NPC support** (p.71) — *new chapter in v5.02*. Rank + Might/Charm/Skill +
   HP/EN/RX; Attack = Rank + Skill, Defense = Rank + Charm; Rank doubles as Soak and
   Grit; BLEED downgrades a die 1▟; forced burn drops Rank 1; up to Rank descriptors
   each granting a freebie R▟ die. Suggest a lightweight NPC character type (GM-side)
   or a separate "mooks tracker" panel matching the sheet on p.82. Optional — decide
   with the table whether this app should manage NPCs at all.

### Phase 5 — Crafting and builders (large, rules still settling)

The rulebook itself says "the more developed rules for Crafting aren't ready yet"
(p.70), so keep these loose and data-driven:

1. **Ammo Builder** (p.73). The app already models ammo supply/bury (keep it). Add
   structured **lines** (up to 3 per tile; 1st line −3, 2nd +0, 3rd +3): trigger
   (On Any X +0, On Each X +2, On roll +4), function priced by the X bucket (1–5),
   modifiers (Sticky +X·2, Restriction −1, Repeat +4), and the 🞮/🞧 split (XP cost vs
   Supply threshold, both min 1). A wizard like the Spell Builder; estimated XP
   replaces the current free-form approach for Ammo.
2. **Potion/reagent crafting** (pp.74–75). Reagents are Ammo tiles (Apothecary and
   Geomancer lists are ready-made data). Crafting check: minimum Test = sum of
   reagent XP (GM may raise); impact die = doses. Ship as: reagent template data +
   a crafting helper in the resolution panel (Test calc + doses from impact).
3. **Spell Builder reconciliation** (pp.55–57). v5.02 formalizes the 🗱 system:
   verbs (Buff/Deal/Give/Take/Move/Heal/Show/Shape with listed costs), divergent
   colors +2, Harm by Pool/Skill/Stat (1/2/4), tag costs by XP value, complexity
   riders (and/or +1, tag-swap +2, crit-swap +3, Bot ally +4, Escape! +4), limits
   (−1 slight / −3 very / −5 niche), Sacrifices (Sap −2, Tire −3, Drain −4,
   Witch −6), Duration and Range from the Space & Time table, and chain-to-skill
   accounting. **Audit `js/spellBuilder.js` line-by-line against these tables** —
   it predates v5.02; verify each verb/cost it offers, add missing verbs (e.g.
   `Give [spell dice as skill]` 5🗱, `Heal [burned tile]` 5🗱, `Shape [bot]` 5🗱),
   and confirm how the "did not chain to a spellcast skill tile −2🗱" rule maps to
   the builder's chain handling. This deserves its own focused pass + test file.

## Part 3 — Open questions: working decisions (2026-06-11, pending GM confirmation)

The player's working assumptions, adopted for implementation; revisit if the GM
rules differently:

1. **Weapon Shield readiness** — *optional.* Weapon shields are a manual opt-in
   checkbox in the defense panel; armor shields apply by default. (Implemented.)
2. **`Sticky` tag scope** — *general-purpose.* Sticky can be added to non-Ammo
   items as a normal BD 4 tag. (Implemented in catalog + tag picker.)
3. **Crit/Shield duplicate pricing** — *separate functions.* `Shield: DOWN` protects
   from DOWN while `Crit: DOWN` inflicts it; no duplicate surcharge between them.
   (Implemented.)
4. **Titan "shock boxes"** — *unknown; GM asked.* Shake Off / Sterner Stuff stay
   descriptive-only; implement the Titan pool/spends around them.
5. **Bestial +1 resource** — *fixed when bought*, like a Qi/Id box's resource choice.
   Store the chosen pool on the tag/tile at purchase.
6. **NPCs** — *wanted, GM-side.* Build NPC/mook tracking as a GM-facing feature
   (pairs with the existing campaign GM role in cloud saves).
7. **Crafting depth** — *implement now*, keep loose so v5.03 changes are cheap.
8. **Chain length limit scope** (PR 3 assumption) — "the chain cannot call more
   tiles than the ▟ of the Chained tile" is read as: all tiles pulled in through
   chain links, including nested links, count against the ▟ of the *called* tile
   that started the chain.
9. **Chain maxed-die cost** (PR 3 assumption) — "each maxed die used costs 1
   resource" is read as: each die contributed by a chain-called tile that rolls its
   maximum face costs 1 resource point of the player's choice (EN, RX, or HP). The
   app reports the count after the roll rather than auto-deducting.
10. **Press cost floor** (PR 4 assumption) — a Press always costs at least 1 RX,
    even when repeat + Fast would reduce a Press Action below 1.
11. **Roll-log priority** (user, 2026-06-11) — the table cares more about *which
    tiles were used* in a check than the roll's numeric outcome. Keep
    called/burned/hitched tile tracking faithful; numeric drift (e.g. post-roll
    freebies missing from the log total) is acceptable.
12. **Titan details** (PR 6 assumptions) — Titan ability tags are priced at 2 XP
    (not in the v5.02 glossary); the H/V score is stored as one signed number
    since "H cancels V"; ability spends record their listed H/V automatically
    (Interception and Turn Them are player-directional, adjusted manually);
    the story-beat trade prompts for the GM-granted point count, capped at max
    Titan; "spend Titan as Core or Shadow" is shown as guidance, not automated.
    Special identity tiles are required to have exactly 3 boxes ("It gains a
    third color box").
13. **Stranger details** (PR 7, per decision #5) — the Bestial +1 resource is
    fixed at purchase, stored on the tag as `Bestial: HP|EN|RX`; the +1 is
    granted per typed tag (untyped Bestial tags grant nothing and are flagged
    in review). An exotic skill tile's own first matching exotic tag is free,
    since its +2 base XP includes the tag (matches Violet's 3-XP `sense` tile).
    Celestial rank reads the section's table; the blank Linear cells at ranks
    1 and 6 are filled with Reach and Long respectively.
